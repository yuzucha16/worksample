## Decisions

### 【この件】M0 対応の方針（2026-10-07）

- 決めたこと: M0 対応はビルド時の静的な切り替えにする。M0 ではフットプリントを優先する。動くことを確認してから、速度のチューニングを行う（ユーザーの指示）。
- 根拠: ユーザーの指示（理由の発言は無い）。前の Project の原則「安全性を優先し、速度はチューニング要素」と整合する。
- 却下案: 未検討。
- 行き先: local（この Project に固有の方針）

### 【この件】M0 の除算: 除算を使わない経路を、自動 + 上書きマクロで選ぶ（2026-10-07）

- **更新（2026-10-07）**: ① の `locate` の実装（ビットごとの剰余 `on_boundary`、乗算の範囲検査）と、その `PTRDIFF_MAX` の前提は、下の「M0 の速度のチューニング」で、乗法の逆元（`inv` `shift` を `struct pool` に持つ）に置き換わった。切り替えの方式（②）と持ち込み方（③）は、そのまま。確認の数値（`.text` 360 / 288）は、置き換え前の値。
- 決めたこと（ユーザーが選択）: ① M0 は除算を使わない形にする（D1）。`capacity` は引き算を数えて求め（`blocks_in`）、`locate` は範囲を `offset < capacity * block_size`（乗算）で、境界をビットごとの剰余（`on_boundary`）で見る。② 切り替えは、ARM で `__ARM_FEATURE_IDIV` が無ければ自動で、`POOL_NO_HW_DIV` でどのコアでも強制できる。③ 前の Project の `src/` `tests/` `Makefile` `tools/` をコピーして、この Project で育てる（`archives/` は変えない）。作業は `feature/m0-no-div` ブランチ。
- 根拠: M0 はフットプリント優先の方針。ホストの試験で、除算なしの経路を、ASan・UBSan つきで同じテストにかけるため、強制用のマクロが要る。API と `block_size` の制約を変えない。
- 却下案: D2（全コアで 2 のべき乗に丸める。ブロックが最大 2 倍に膨らむ）、D3（前の F1。全体を筆算にし、M0 の最小化を目指さない）。切り替えの「ビルドオプションでの明示のみ」「自動のみ」は選ばれなかった。
- 確認済み（2026-10-07、WSL）: `make check` 終了コード 0（新規の `test-soft` `test-soft-o2` を含む）。M0 / M0+ は `.text` 360、`.data` 0、`.bss` 0、未定義シンボルなし。**M3 / M4 は、変更前（`.text` 288）とオブジェクトファイルがバイト単位で同一**（`cmp`、`objdump -d` の差分なし。デグレなしの根拠）。
- `on_boundary` の左シフトの桁あふれ対策（キャリーの検査）は、入れない。`bsize` はバッファに収まり、オブジェクトの大きさは `PTRDIFF_MAX` 以下なので、`rem < bsize` の左シフトはあふれない（最初はキャリーの検査を入れて `.text` 366、外して 360。理由はコメントに残した）。この前提（オブジェクトの大きさ ≤ `PTRDIFF_MAX`）は、C 規格が保証するものではなく、GCC の実装上の制限。確認: 未実施（テストでは、そのサイズのバッファを作れない）。
- 行き先: local（この Project に固有の設計判断）

### 【この件】M0 の速度のチューニング: S2（初期化ループの統合）、S3（検査の削減）、S4（逆元をキャッシュ）を取り込む（2026-10-07）

- 決めたこと（ユーザーの指示）: 対象 M0 は乗算が 32 サイクル（小型乗算器）。S3（`is_initialized` を縮める）は、初期化されていることを設計として保証したうえで取り込み、テストを強化する。S4（`struct pool` に `inv` と `shift` を持つ。RAM が 1 プールにつき 8 バイト増える）を許容する。S1（呼び出しごとに逆元を計算する）は、S4 に置き換えた（32 サイクルの乗算では、呼び出しごとの乗算が効かないため）。作業は `feature/m0-speed` ブランチ。
- 根拠: 乗算 32 サイクルの見積もり（`docs/log.md` 2026-10-07）で、S4 だけが `pool_free` を大きく短縮した（563 → 103 サイクル）。
- 設計: 初期化の保証は `docs/design.md` の 7 節（`pool.h` に正本）。`pool_alloc` と `pool_free` は未初期化（全ゼロ）だけを弾き、不変条件は再検査しない。`pool_check` は I1、`block_size`、`capacity` を検査する。
- 判断（AI。ユーザーに未確認）: ① S3 は全コアに適用した（M3 / M4 も同じ契約にするため）。M3 / M4 のオブジェクトは変更前と同一でなくなった（288 → 280。縮んだ）。② `pool_check` に I5（`shift` と `inv` の整合）の検査を足すと、`.text` が 36 バイト増える（388）ので、入れなかった。I5 は、テストで検証する。③ `POOL_SOFT_DIV` の判定を `pool.h` に移した（構造体の配置が条件で変わるため。呼び出し側のすべての翻訳単位を、同じ条件でコンパイルする必要がある）。
- 却下案: S1 のまま（呼び出しごとに逆元。乗算が遅いと効果が小さい）、`pool_check` に I5 の検査を足す（36 バイト増）。
- 確認済み（2026-10-07、WSL）: `make check` 終了コード 0（新規の `test-white` `test-white-soft` を含む）。M0 / M0+ は `.text` 352（以前 360）、M3 / M4 は 280（以前 288）、`.data` と `.bss` は 0、未定義シンボルなし。速度（命令シミュレータ。`docs/log.md` に条件）は乗算 32 サイクルで、`pool_free` 563 → 103、`pool_alloc` 41 → 17、`pool_check`（64 ブロック）33,910 → 5,745、`pool_init` 1,330 → 1,104（乗算 1 サイクルでは 532 → 72、41 → 17、31,926 → 3,761、1,299 → 856）。変異テストは、各変異を検出した。
- 行き先: local（この Project に固有の設計判断）
