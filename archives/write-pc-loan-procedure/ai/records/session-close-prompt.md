# 部屋の AI への指示: close の判断（記録）

この文書は、`room close` が部屋の AI に渡した指示の記録（再現用）。作成日: 2026-10-12。

## 前提

- 作業ディレクトリは、この Project の `ai/`（部屋の中では `/mnt/room/write-pc-loan-procedure`）。`ctx/README.md` が、Project の README の写し（読み取りのみ。完了条件と制約が書いてある）。
- ユーザーの指示（2026-10-12）: この Project はテスト版なので、未完了でも構わない。**中間状態にしないため、未記入の欄はすべて「完了」として扱い**、Project を閉じる。閉じたあとは `archives/` に置いたままにする（戻さない）。
- 触ってよいのは `docs/log.md`（上書き）と、`out/close.md`（新規）だけ。それ以外のファイルは変更しない。

## やること（`close` の判断の部分。`workflow-kit` の `close-hook.md` の手順 1〜4）

1. **完了条件の確認**: `ctx/README.md` の完了条件を読み、`out/pc-loan-procedure.html` と `docs/` の状態で、どこまで満たしているかを書く。未記入の欄は「完了扱い」とした上で、実際に残っている欄を一覧にする（運用で埋める欄として、Area に渡す）。
2. **暫定の見直し**: 暫定にしていた決定（制約、方式、数値）があれば挙げる。なければ「なし」と書く。
3. **未解決の振り分け**: 残りの Next Actions と Open Questions を、(a) 親の Area に渡す、(b) 破棄、のどちらかに振り分ける。(a) の項目には、【案件】のラベルを付ける。
4. **ナレッジ化の候補**: 【汎用】の項目（ほかの Project にも通じる知見）があれば一覧にする。なければ「なし」。`stock` は実行しない。
5. **`docs/log.md` を上書き**: 閉じたことと結果、渡した項目を、次に読む人（Project を `archives/` から読み返す人）が分かる現在状態として書く。

## 出力

`out/close.md` に、上の1〜4を見出しで分けて書く。【案件】の項目は、`- 【案件】<1行の項目>` の形で、1行1項目にする（`room close` が Area の `inbox.md` に転記する）。

## 制約

- 顧客データ・社外秘は扱わない（この Project には無い）。
- `ctx/` と、ここに書いた以外のファイルは変更しない。
- 判断に迷う点は、`out/close.md` の末尾の「確認したいこと」に書く。
