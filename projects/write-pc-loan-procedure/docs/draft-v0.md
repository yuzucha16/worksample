# PC 貸し出し表の管理 手順書（初稿 v0・レビュー用）

状態: **AI の初稿。未承認**。`【】` は記入欄、`※` はレビューで決めたい点。A4 1〜2枚に収める。

## 0. この手順書でやること

会社の PC 5台を貸し出すとき、「いつ・誰に・どの PC を貸したか」を1つの表に残し、なくなったらすぐ気付けるようにします。

- 貸し出し表の置き場: 【場所】
- 困ったとき・紛失のとき: 【連絡先】

## 1. 貸し出し表（1つだけ）

表は1つだけ使い、コピーは作りません。書くのは次の列です。

| 列 | 内容 |
|---|---|
| PC の番号 | 1〜5 |
| 機械の番号（MAC アドレス） | 貸し出す前に控える（下の「準備」） |
| 借りた人 | 氏名 |
| 貸した日 | 年月日 |
| 返す予定の日 | 年月日 |
| 上司の承認 | メールを保存した場所、または日付 |
| 返した日 | 返却時に書く |
| 状態 | 貸出中 / 貸出可 |

準備（最初の1回だけ）: 5台の機械の番号を控えて、表に書きます。確認方法: 【管理者に聞く】

## 2. 貸すとき

1. 借りたい人から、依頼を受ける。
2. 上司が貸し出しを承認したことを、メールで確かめる。メールは【保存場所】に保存する。承認がなければ貸さない。
3. 空いている PC を選び、表の「状態」が「貸出可」であることを確かめる。
4. 表に、借りた人・貸した日・返す予定の日・承認の保存先を書き、状態を「貸出中」にする。
5. PC を渡す。

## 3. 返してもらうとき

1. PC を受け取り、表の「返した日」を書く。
2. 次の人に貸せる状態にする: 【初期化・清掃などの内容。※決める】
3. 状態を「貸出可」にする。

## 4. 週に1回の確認（毎週【曜日】）

1. 表を見て、「貸出中」の人と PC を一覧にする。
2. 【借りている人全員】に、「いまも手元にありますか」とメールで聞く。
3. 返す予定の日を過ぎている人には、その場で返却を頼む。
4. 返事がない人、または「手元にない」という返事は、次の「なくなったとき」へ進む。

## 5. なくなったとき（すぐに）

次の3つを、見つけた時点ですぐに行います。

1. 【連絡先 1】に電話・連絡する。
2. 表の該当の行に、気付いた日時と状況を書く。
3. 【3つ目の手。既存の取り決めから】

詳しい対応は、【既存の取り決めの場所】を見る。

## レビューで決めたい点（初稿には含めない）

### ※A 貸し出し表の置き場

要望: シンプル、長期間使える、二重管理なし、権限の管理が楽。

| 案 | 長所 | 短所 | 評価 |
|---|---|---|---|
| ① 共有フォルダの表計算ファイル1つ | 1か所だけ。フォルダの権限で、見られる人と書ける人を分けられる。長く使える | 同時に開くと上書きの注意が要る。会社の共有フォルダの有無が前提 | **推奨**（前提が合えば） |
| ② 紙の台帳 | 道具が要らない。誰でも書ける | 検索と週次の一覧が手作業。紛失・汚れ。遠隔で見られない | 5台なら成り立つが、「早く気付く」に弱い |
| ③ 共有のオンライン表 | 同時に編集できる。履歴が残る | 社外サービスの利用可否の確認が要る。権限の設計が要る | 会社の方針次第 |

### ※B 「紛失に早く気付く」の工夫（AI の提案。未承認）

週1回の確認だけだと、最長で約1週間気付きません。次の案があります。

- 貸すときに「返す予定の日」を必ず決め、期間を短くする（例: 最長1週間）。週次の確認で、期限切れを必ず拾う。
- 週次の確認を、「返す予定が来週までの人」に絞ったメールにして、手間を減らす。
- 確認の頻度を週2回にする（負担は増える）。

推奨: 1つ目と2つ目の組み合わせ。頻度は変えず、期限を短くする。

### ※C そのほか

- 「機械の番号」の呼び方と確認方法を、読み手に通じる言葉にする。
- 返却時の「貸し出し可能状態」の中身。
- 緊急プロトコルの連絡先と、最初の3手（既存の取り決めの内容が要る）。
