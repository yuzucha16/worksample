# write-pc-loan-procedure

庶務さん（事務員さん）に PC 貸し出し表の管理を依頼するための、手順書のひな形を作る。所属 Area: [[areas/office-admin/README|office-admin]]。

## 完了条件

事務員さんが、この手順書だけで作業を始められること。ユーザーが渡すチェックリスト（下）を、最低限クリアしていること。（ユーザーの指示: 2026-10-07）

## チェックリスト（ユーザーが指定した資料。2026-10-07）

1. 利用者から貸し出し要望を受ける。
2. 利用者は上司に借りることの承認を取っていること。エビデンスはメールで充分。
3. 5台の PC の MAC アドレスを控えて貸し出す。
4. 1週間に1度、棚卸しのためのメール確認をする。
5. 紛失時は即座に緊急プロトコルを発動する。
6. 返却時に PC を貸し出し可能状態にする。

上の6項目以外は、論点整理・選択肢の検討・判断材料の提供の対象にする（資料としては扱わない）。

## 進め方（ユーザーの指示: 2026-10-07）

1. markdown を中間成果物として、ユーザーとレビューする。
2. ゲート承認の後に、html で最終成果物にする。
3. 運用しながら、手順書を改良する（改良は Area `office-admin` で続ける）。

## 制約

- 専門用語を使わない。
- 紛失時の緊急プロトコルは、既存の取り決めがある。手順書には「連絡先と最初の3手」だけ書く（実値は記入欄）。
- 貸し出し表の形式と置き場は未定。ひな形で選択肢を比べる。ユーザーの希望: できるだけシンプルで長期間使える運用、二重管理をしない、アクセス権の管理が容易。

## 成果物

- `docs/` 配下のレビュー用 markdown（ひな形）と、ゲート承認後の html。名前と構成は、初稿のときに決める。

## 範囲外

- 細かい図表の作成（mermaid による UML 表記は許容）。
- 精緻な手順書（A4 1〜2枚。どうせ見ないため）。
